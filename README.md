# attendance-helper-ios

Scriptable 今日考勤小组件 + 快捷指令提醒。

项目位置：`scriptable/AttendanceHelper.js`

提供今日工时倒计时、上下班打卡状态、月度考勤日历、异常核查、桌面小组件样式配置及自动提醒。

## 功能概览

- 今日打卡：实时计算已工作时长、剩余工时和预计可下班时间。
- 桌面小组件：支持小号、中号和大号布局。
- 多主题组件：提供 Cyberpunk、Fitness、Minimal、Heatmap 四种风格。
- 独立样式配置：不同尺寸可以使用不同风格。
- 考勤管理：查看月历、每日打卡记录和月度统计。
- 异常核查：人工确认正常、确认异常或恢复系统原判。
- 请假核算：登记已批准请假时长，重新计算应出勤时间。
- 自动提醒：预约接近 9 小时的提醒，检查是否已经满足下班条件。
- 本地缓存：网络失败时使用已有考勤快照。
- 锁屏组件：支持矩形、圆形和日期上方一行。
- 公开仓库更新：匿名下载最新脚本，不需要 GitHub Token。

## 更新到手机

仓库是公开的。Scriptable 直接下载原始文件，不需要 GitHub Token。

公开地址：

```text
https://raw.githubusercontent.com/biannian/attendance-helper-ios/main/scriptable/AttendanceHelper.js
```

浏览器打开这个地址，应看到脚本源码。如果是 404，检查仓库是否设置为 Public，以及 `main` 分支上是否已经存在该文件。

### 第一次安装

1. 打开仓库里的 `scriptable/InstallAttendanceHelper.js`。
2. 全选复制。
3. 在 Scriptable 新建脚本，粘贴后运行一次。
4. 不需要填写 GitHub Token。
5. 安装器会下载 `main` 分支最新的 `AttendanceHelper.js` 并写入 Scriptable。
6. 桌面小组件选择 `AttendanceHelper`。

### 更新已有脚本

如果手机上仍然是旧版本，使用安装器替换一次。

之后可以通过以下方式更新：

- 再次运行安装器。
- 在考勤脚本菜单中选择「更新脚本」。
- 快捷指令参数第一行填写 `update`。

以上方式均从公开仓库匿名下载，不会询问或发送 GitHub Token。

如果旧脚本提示「下载内容不是打卡脚本」，可重新运行最新版安装器。

安装器会替换脚本源码，但保留本机钥匙串中的账号配置。

**安全说明：**

账号、密码、设备 ID 和登录 Token 均保存在本机，不要提交到 GitHub 仓库，也不要写入公开脚本源码。

## 账号、密码、设备 ID

账号资料通过快捷指令参数传递，一条指令同时包含动作和账号信息。

参数采用四行文本：

```text
refresh
账号
密码
设备ID
```

第一行是动作，后面三行是同一组账号、密码和设备 ID。

不同操作只需要修改第一行：

| 动作 | 用途 |
|---|---|
| `refresh` | 刷新今日考勤 |
| `leave` | 离开公司检查 |
| `schedule9` | 预约工时提醒 |
| `near9` | 检查接近或达到 9 小时 |
| `update` | 更新脚本 |

脚本运行后会把账号资料保存在 Scriptable Keychain。

更换账号时，修改快捷指令中的三项账号信息。脚本会清除旧账号对应的登录 Token 和考勤快照，避免不同账号的数据混用。

不需要另外建立只负责保存账号的快捷指令。

## 运行模式

在快捷指令或 Scriptable 中通过参数指定运行模式。

| 参数 | 说明 |
|---|---|
| `widget` | 手动预览组件。桌面和锁屏刷新会拉取新数据，失败时使用当天快照 |
| `refresh` | 快捷指令刷新：拉取最新考勤数据、更新本地快照，不弹出预览 |
| `leave` | 离开公司检查，根据实际工时判定考勤状态及是否漏打下班卡 |
| `schedule9` | 中国工作日预约接近 9 小时提醒 |
| `near9` | 定时检查是否接近或已经满足 9 小时，并同步判定下班卡 |
| `week` | 在 Scriptable 中全屏打开考勤历史管理页面 |
| `debug` | 查看数据解析结果和考勤判定信息 |
| `update` | 从公开 GitHub 仓库匿名下载最新脚本 |
| `account` | 通过快捷指令参数写入账号、密码和设备 ID |

## 桌面小组件

支持小号、中号和大号组件。

不同尺寸可以独立选择风格，不需要统一使用同一种主题。

### 1. 四种视觉风格

#### Cyberpunk 赛博仪表盘

科技感、深色 HUD 风格。

- 深色背景和霓虹青色强调。
- 大号工时数字。
- 工时进度条。
- 上下班时间和预计达标时间。
- 根据组件尺寸展示不同的信息层级。

#### Fitness 环形进度

参考 Apple Fitness 的环形活动进度设计。

- 环形工时进度。
- 多层状态指示。
- 今日累计工时。
- 上下班时间。
- 剩余工时信息。

#### Minimal 极简电子墨水

黑白灰极简风格。

- 大字号数字。
- 简洁的时间信息。
- 低干扰配色。
- 使用简洁标记区分正常、异常和休息日。

#### Heatmap 月历热力图

以考勤日历为核心。

- 不同颜色区分正常、待核查和异常。
- 大号组件重点展示整月考勤。
- 中小号组件采用适合屏幕尺寸的精简布局。
- 突出当日状态和月度统计。

### 2. 选择组件风格

在 Scriptable 中手动运行 `AttendanceHelper`，打开考勤管理页面。

进入设置中的「小组件样式」，可以分别配置：

| 组件尺寸 | 可选风格 |
|---|---|
| 小号 | Cyberpunk / Fitness / Minimal / Heatmap |
| 中号 | Cyberpunk / Fitness / Minimal / Heatmap |
| 大号 | Cyberpunk / Fitness / Minimal / Heatmap |

每种尺寸可以独立设置。

例如：

- 小号：Minimal
- 中号：Fitness
- 大号：Heatmap

选择样式后可以预览对应尺寸，确认后保存。

样式配置保存在本机，不需要修改脚本源码。切换配置不会清除考勤快照和账号信息。

### 3. 组件布局参数

长按桌面小组件，选择「编辑小组件」，在 Scriptable 参数栏填写：

| 参数 | 中号 | 大号及很大号 |
|---|---|---|
| 留空 | 今日倒计时、进度条和打卡状态 | 今日布局 + 考勤月历 |
| `today` | 今日打卡 | 今日布局 + 考勤月历 |
| `stats` | 近 7 天统计 | 工作日：今日考勤 + 近 14 天统计；休息日：仅统计 |

小号和锁屏组件仍使用各自的布局。

样式配置与布局参数是两个独立设置：

- 布局参数决定展示哪些考勤信息。
- 样式配置决定这些信息如何排列和呈现。

大号组件无论选择哪种主题，工作日都会在顶部展示今日考勤核心信息；`stats` 布局也会保留这一区域。休息日不显示今日考勤，避免把休息日误显示为未打卡。

大号组件的默认布局统一在顶部展示今日考勤核心信息：

- 实时下班倒计时（未打上班卡时显示等待打卡）。
- 上班打卡时间、预计可下班时间、下班打卡时间。
- 工时进度和当前考勤状态。

今日信息区下方仍按所选风格展示不同内容：赛博风格显示近 7 天轨迹和近期记录，环形风格显示月度达标与工时柱状图，极简风格显示月度账本和近期记录，热力图风格保留整月考勤日历。

主题名称只用于管理页面的样式选择，不会显示在桌面小组件上；组件标题使用「今日考勤」等功能性文案。

V9 大号布局调整：

- 左右边距：16pt。
- 上下边距：10pt。
- 月历高度根据布局动态计算。
- 七列日期格保持统一宽度。

### 4. 手动预览

在 Scriptable 中手动运行脚本，进入小组件预览入口。

支持预览：

- 小号组件。
- 中号组件。
- 大号月历组件。

预览时应使用对应尺寸的渲染布局，不应因设备当前桌面组件尺寸而覆盖预览尺寸。

## 手动刷新小组件

小号和锁屏组件沿用原来的刷新链接，会打开快捷指令「更新打卡小组件」。

这条快捷指令执行两个操作：

1. Scriptable → 运行脚本 `AttendanceHelper`。
   - 参数贴入四行文本。
   - 第一行填写 `refresh`。
   - 后面依次填写账号、密码、设备 ID。
   - 关闭「运行时显示」。

2. Scriptable → 刷新所有小组件。
   - 关闭「显示运行时」。

早上 8:00 的自动化直接运行这条「更新打卡小组件」快捷指令，不需要另外建立一条只负责刷新的指令。

### 自动刷新策略

- 工作日 8:00 至 11:00，还没有上班卡时，大约每 10 分钟重新拉取一次。
- 获取到上班卡后，中号和大号今日布局约每 30 分钟请求刷新进度。
- 到达可下班时间时请求刷新。
- 11:00 仍未打卡，或当天已经结束，则等待下一个工作日早上。

实际刷新时间由 iOS WidgetKit 决定，系统可能延迟刷新请求。

脚本侧会给打卡请求添加时间戳，点击地址使用 `x-callback-url` 并携带时间戳，减少缓存导致的数据不更新问题。

## 考勤管理页面

手动运行 Scriptable 脚本，进入考勤管理页面。

管理页面采用 WebView 实现，主要用于查看考勤、调整异常判定和配置小组件。

### 1. 月度考勤日历

- 按周一至周日排列。
- 支持上月、下月和回到本月。
- 点击日期查看当天打卡记录。
- 使用颜色区分正常、待核查、确认异常、进行中和休息日。
- 点击待核查记录可直接进入核查。

进入页面或切换月份后，会自动补查当月截至今天缺少快照的工作日。

查询失败时，该日期保留待核查状态，不直接判定为正常。

### 2. 每日考勤详情

点击日期可以查看：

- 上班卡时间。
- 下班卡时间。
- 实际工作时长。
- 系统原始判定。
- 本机人工核查结果。
- 原始离场卡记录。
- 已登记的请假时长。

考勤详情只展示本机获取的原始记录和计算结果，不会修改企业考勤服务器中的原始工卡。

### 3. 异常考勤核查

核查操作保持轻量化，不需要填写额外说明。

支持三种处理方式：

| 操作 | 说明 |
|---|---|
| 确认正常 | 人工确认当天考勤正常 |
| 确认异常 | 人工确认当天确实存在异常 |
| 恢复原判 | 撤销本机人工修正，恢复系统原始判定 |

核查结果只影响本机考勤展示和统计，不修改企业服务器中的原始工卡。

核查结果按账号和日期保存在本机，可以随时撤销。

### 4. 请假核算

登记请假时，可以选择：

- 请假已核实，确认正常。
- 仅记录请假时长，按调整后的应出勤时间重新计算。

例如：

目标工时为 9 小时，已批准请假 2 小时，则实际应出勤时长按 7 小时计算。

以前仅登记过请假时长的日期，仍然可以重新打开核查并确认。

### 5. 月度统计

月历下方显示当月统计：

- 平均上班时间。
- 平均下班时间。
- 平均实际工作时长。
- 正常天数。
- 待核查天数。
- 确认异常天数。

平均数据按照各自已有的有效工作日记录计算，不把休息日或缺失记录当成正常数据。

## 锁屏和休息日

锁屏支持：

- 矩形组件。
- 圆形组件。
- 日期上方一行。

桌面和锁屏组件根据当天第一张上班卡计算可下班时间，并显示系统倒计时。

目标时间之前的门禁刷脸视为临时外出，不作为下班卡，倒计时继续计算。

每次成功拉取的打卡都会写入本地快照。锁屏或网络请求失败时，优先使用已有快照，并按照相同规则展示。

### 休息日和节假日

- 休息日不显示考勤内容。
- 法定节假日不显示考勤内容。
- 调休补班按照工作日处理。
- 节假日接口失败时，默认按照周一至周五判断。

---

## 考勤判定

当天只把目标可下班时间起至当前时刻之间的离场刷脸计为下班卡。

历史工时按照接口记录的上下班卡时间计算。

基本判定规则：

1. 未打上班卡：未打卡。
2. 已打上班卡，但没有有效下班卡：漏打下班卡或仍在工作。
3. 历史工作日有下班卡，但工时未满应出勤时长：还差 X小时Y分钟。
4. 有有效下班卡且工时达到应出勤时长：考勤正常。
5. 已人工核查的日期：按照本机核查结果展示，同时保留系统原始判定。

请假时长会参与应出勤时长计算。

人工核查不会覆盖服务器原始数据。

## 通知

考勤通知保持简洁，只有两行：

- 标题：当前考勤状态。
- 副标题：上班卡和下班卡信息。

已经打下班卡时，显示实际下班时间。

还没有打下班卡时，显示「未打」以及可下班时间。

还差的时长按照小时和分钟显示，例如：

```text
还差 1小时20分钟
```

通知图标使用 Scriptable 应用图标，接口不支持更换通知图标。

## 还差时长与倒计时

差额按照小时和分钟显示：

- 不足 1 小时：只显示分钟。
- 整小时：只显示小时。
- 非整小时：同时显示小时和分钟。

例如：

| 剩余时间 | 显示 |
|---|---|
| 35 分钟 | 还差 35分钟 |
| 1 小时 | 还差 1小时 |
| 1 小时 20 分钟 | 还差 1小时20分钟 |
| 2 小时 5 分钟 | 还差 2小时5分钟 |

### 距可下班

倒计时根据当前时间实时计算。

到达可下班时间后，组件请求刷新并切换到考勤状态。

### 已打下班卡

实际工时按照上班卡和下班卡之间的时间差计算。

## 本地数据与安全

本项目将账号数据和考勤快照保存在本机。

- 账号、密码和登录 Token 使用 Scriptable Keychain。
- 考勤快照用于网络失败时恢复今日状态。
- 人工核查结果按账号和日期保存。
- 小组件配置保存在本地偏好设置。
- 不同账号的数据相互隔离。
- 更新脚本不会主动清空钥匙串中的账号资料。

不要将真实账号、密码、设备 ID、Token 或个人考勤数据提交到公开仓库。
