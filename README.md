# attendance-helper-ios

Scriptable 今日打卡小组件 + 快捷指令提醒（`scriptable/AttendanceHelper.js`）。

## 更新到手机

仓库是公开的。Scriptable 直接下载原始文件，不需要 GitHub Token。

公开地址：

```text
https://raw.githubusercontent.com/biannian/attendance-helper-ios/main/scriptable/AttendanceHelper.js
```

浏览器打开这个地址，应看到脚本源码。如果是 404，仓库还没设成 Public，或 `main` 上还没有这个文件。

第一次装到手机：

1. 打开仓库里的 `scriptable/InstallAttendanceHelper.js`，全选复制。
2. 在 Scriptable 新建脚本，粘贴后运行一次。不要填 Token。
3. 安装器会把 `main` 上的最新 `AttendanceHelper.js` 写进 Scriptable。小组件选这个脚本。

手机上如果还是旧脚本，菜单里的「更新脚本」仍会要 Token。先用上面的安装器替换一次。替换之后：

- 再运行安装器，或
- 在打卡脚本菜单里点「更新脚本」，或
- 快捷指令参数第一行填 `update`

这三种都会匿名下载，不再询问、也不再发送 GitHub Token。

如果旧脚本提示「下载内容不是打卡脚本」，可重试一次。若仍出现提示，复制本仓库最新版的安装器到 Scriptable 并运行一次。安装器会替换脚本源码，保留钥匙串里的账号设置。

钥匙串里的打卡 Token、账号、密码和设备 ID 不会被覆盖清掉。脚本文件会按仓库 `main` 上的版本整份替换。账号和密码不要写进仓库。

## 账号、密码、设备 ID

这三项不要写进脚本。写在快捷指令参数里，一条指令同时带上动作和账号。

参数用四行文本：

```text
refresh
账号
密码
设备ID
```

第一行是动作。离开公司把第一行改成 `leave`，预约提醒改成 `schedule9`，定时检查改成 `near9`。后面三行都是同一组账号、密码、设备 ID。不用再单独做一条只负责保存账号的指令。

脚本运行后会把这三项记进钥匙串。换账号时改快捷指令里的三行，旧登录 Token 和打卡快照会清掉。

## 模式

| 参数 | 说明 |
|------|------|
| `widget` | 手动预览。桌面和锁屏刷新会拉新数据，失败时用今天的快照 |
| `refresh` | 快捷指令点击刷新：拉最新数据、写入快照，不弹预览 |
| `leave` | 离开公司：按打卡工时判定考勤，识别是否漏打下班卡。四行参数的第一行填 `leave` |
| `schedule9` | 中国工作日预约快满 9 小时提醒 |
| `near9` | 定时检查快满 / 已满，已满时同步判定下班卡 |
| `week` | 在 Scriptable 中全屏打开考勤历史 |
| `debug` | 查看解析结果与考勤判定 |
| `update` | 从公开仓库下载最新脚本，不需要 GitHub Token |
| `account` | 快捷指令写入账号、密码、设备 ID |

## 选择小组件布局

长按桌面小组件，选择「编辑小组件」，在 Scriptable 的参数栏填写：

| 参数 | 中号 | 大号 |
|------|------|------|
| 留空 | 今日倒计时、进度条和打卡状态 | 中号的今日布局＋考勤月历 |
| `today` | 今日打卡 | 只显示中号的今日布局 |
| `stats` | 近 7 天统计 | 只显示考勤月历 |

小号和锁屏仍使用各自的布局。大号月历从本机快照读取记录。在支持交互的 Scriptable 和 iOS 17 或更新版本中，可用箭头在桌面原地翻月。旧版用箭头打开对应月份的核查页。在大号月历上点月份标题，可进入对应月份补查和核对打卡。

## 手动刷新小组件

小号、仅展示今日的大号和锁屏组件沿用原来的刷新链接，会打开快捷指令 `更新打卡小组件`。这条指令做两件事：

1. Scriptable → 运行脚本 `AttendanceHelper`。参数贴四行文本，第一行是 `refresh`，后面是账号、密码、设备 ID。关闭「运行时显示」。
2. Scriptable → 刷新所有小组件。关闭「显示运行时」。

早上 8:00 的自动化直接运行这条 `更新打卡小组件`，不用再做一条只刷新的指令。

工作日 8:00 到 11:00，还没有上班卡时大约每 10 分钟再拉一次。有上班卡后由系统显示倒计时，中号和大号今日布局约每 30 分钟请求刷新进度条，并在可下班时间请求刷新。实际刷新时机由 iOS 决定。11:00 仍未打卡，或当天已经结束，就等到下一个工作日早上。

脚本侧会给打卡请求加时间戳，点击地址使用 `x-callback-url` 并带时间戳。

## 考勤历史

点击桌面中号组件或大号的月份标题，进入按周一至周日排列的月历。页面支持上月、下月和回到本月。月历下方集中列出待核查异常。点日期或「核查」，可查看上下班卡、实际工时、应出勤和系统原判。

登记已批准的请假时长后，页面会扣减应出勤时长并重新判断。全天请假可按 9 小时登记。人工确认正常时需填写说明，可随时撤销。核查结果按账号和日期保存在本机，原始工卡及公司系统记录保持原样。

页面会逐日补查选月中缺少快照的工作日，查询失败会列为待核查。点顶部「配置」可选择组件主题和提前提醒分钟数。

## 锁屏和休息日

锁屏支持矩形、圆形和日期上方一行。桌面和锁屏组件从当天第一张上班卡算出可下班时间，并显示系统倒计时。目标时间之前的门禁刷脸视为临时外出，倒计时继续走。每次拉到的打卡都会写入快照，锁屏或网络失败时也按同一规则显示。

休息日和法定节假日不显示考勤内容。调休补班仍显示。节假日接口失败时按周一到周五判断。

## 考勤判定

当天只把目标时间起至当前时刻之间的离场刷脸计为下班卡。历史工时按接口记录的上下班卡时间计算。

1. 未打上班卡 → 未打卡  
2. 无下班卡 → 漏打下班卡  
3. 历史日有下班卡但工时未满 9 小时 → 还差 X小时Y分钟
4. 有下班卡且工时已满 → 考勤正常  

## 通知

考勤通知只有两行：标题是状态，副标题分成上班卡和下班卡。已经打下班卡时写下班时间；还没打时下班卡写「未打」，并附上可下班时间。还差的时长按小时和分钟写，例如「还差 1小时20分钟」。通知图标是 Scriptable 应用图标，接口不能更换。

## 还差时长

差额按小时和分钟显示，例如还差 1小时20分钟。不足 1 小时仍写分钟，整小时不补 0 分钟。

- **距可下班**：倒计时按当前时间计算，到点后组件请求刷新并切换为考勤状态
- **已打下班卡**：工时以两张卡之间的时长计算。
